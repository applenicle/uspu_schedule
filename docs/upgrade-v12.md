# USPU Schedule v12 — общий кэш и читаемый интерфейс

- **Общий кэш:** Neon PostgreSQL хранит расписания независимо от посетителей и устройств. После первого получения любой запрос `/api/schedule` читает общий снимок; `cached: true`, `stale` и `age_seconds` помогают диагностике. Для успешных ответов добавлен 30-секундный Vercel CDN-кэш; ответы с `pending: true` не кэшируются.
- **Фоновое обновление:** заявки на одну группу объединяются, часто открываемое расписание остаётся активным, новые ещё не загруженные запросы получают приоритет перед обновлением старых. Данные не удаляются при недоступности УрГПУ.
- **Ограничения:** первый запрос к группе, которую ещё никто не открывал, требует работы московского сборщика, обычно до следующего цикла опроса. Не запускайте массовый сбор всех 937 групп.
- **Интерфейс:** недельные карточки больше не сжимаются в 7 узких столбцов на ноутбуке; длинные кабинеты и преподаватели не разбиваются на отдельные буквы; реальные подгруппы подписаны, а для параллельных записей без номера группа не выдумывается.
- **Бот:** даты недели выделены прописными буквами, убраны повторяющиеся служебные подписи и статус обновления, кнопки дня названы однозначнее, кнопка Mini App помечена как `success` (её отображение зависит от клиента Telegram).

## Развёртывание
1. Скрипт `apply_uspu_v12.sh` проверяет дерево v11, создаёт коммит и делает push (из WSL). Текущий worker на московском VPS **не перезапускать**: изменения очереди выполняются в API на Vercel.
2. Убедитесь, что деплой Ready, и откройте ранее загруженную группу с другого устройства: занятия должны появиться сразу. Принудительная перезагрузка страницы может понадобиться для обновления статики Next.js.
3. Проверьте `GET /api/schedule?kind=group&id=Дг-304`: `cached:true`, `pending:false` и ненулевой массив `lessons`. В дальнейшем `stale:true` означает возраст кэша, но расписание остаётся доступным.
4. Если новый пользователь впервые открывает неизвестную группу, Vercel ставит одну запись в `interests`, и worker подтянет её автоматически. Не запускайте отдельные jobs для каждого посетителя.

Новых таблиц или переменных окружения нет. Структура FSD сохранена. Полную сборку Next.js необходимо подтвердить через Deployments в Vercel.
