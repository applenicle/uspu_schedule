# УрГПУ Schedule v10 — мобильная вёрстка, favicon и Telegram-бот

## Что изменилось

- Уроки сохраняют полную цветовую заливку по типу занятий.
- Исправлен многоколоночный layout: длинные ФИО больше не должны сжиматься до одной буквы в строке, аудитория располагается отдельно справа.
- Названия помещений приводятся к компактному формату (`М1-313 · УК М9`), полный оригинал остаётся в `title` кнопки.
- Верхнее меню темы использует более узнаваемые значки солнца и луны. Режим «Как на устройстве» сохраняется.
- `src/app/icon.png` и `src/app/apple-icon.png` имеют прозрачный фон (RGBA). Рисунок — открытая книга в стилистике проекта.
- Новый `POST /api/telegram/webhook` позволяет **самому Telegram-боту отвечать** HTML-расписанием без регистрации на сайте.
- `/api/telegram/message` остаётся прежним read-only предпросмотром, не отправляет сообщения самостоятельно.

## Telegram (после Ready-деплоя v10 в Vercel)

1. Использовать **отдельный токен бота расписания** из BotFather. Не путать с `WORKER_TOKEN` (VPS).
2. В Vercel → `uspu-schedule` → Settings → Environment Variables (Production) создать:
   - `TELEGRAM_BOT_TOKEN` — токен BotFather.
   - `TELEGRAM_WEBHOOK_SECRET` — новый секрет `openssl rand -hex 32`.
   - `PUBLIC_SITE_URL=https://uspu-schedule.vercel.app` (можно не задавать, если используется дефолтный домен).
3. Выполнить Redeploy нового коммита (чтобы Production получил переменные).
4. В WSL выполнить `bash ~/uspu_schedule/scripts/register-telegram-webhook.sh`. Он попросит токен и webhook-секрет без вывода их на экран, проверит наличие старого webhook и перед заменой другого URL запросит подтверждение.
5. В приватном чате с ботом проверить:
   - `/start`
   - `дг304` или `/group ДГ-304` — ближайший день с занятиями
   - `/today ДГ-304` — сегодня
   - `/tomorrow ДГ-304` — завтра
   - `/week ДГ-304` — неделю (с ограничением 4096 символов на сообщение)
   - `/teacher Микушина Марина Михайловна` — расписание преподавателя

Бот использует существующие таблицы `catalog`, `interests`, `schedules`. Если расписание ещё не было собрано, создаёт заявку на синхронизацию; нужно повторить команду после обработки worker. У бота нет собственной регистрации и нет отдельной таблицы пользователей — Telegram передаёт ID чата для ответа, но наше приложение не записывает его в БД.

**Важное предупреждение:** `setWebhook` для существующего токена бота переключает **единственный** webhook этого бота. Не подключайте токен другого рабочего Telegram-бота без проверки. Если у бота уже установлен другой webhook, скрипт попросит подтверждение.

## Проверки

- `npm test`
- `node scripts/check-jsx.cjs` (если окружение содержит TypeScript в `/usr/local/slides_js` — локальная проверка в рабочей среде; в обычном WSL этот путь может отсутствовать)
- `npm run build` при установленных зависимостях
- `curl -I https://uspu-schedule.vercel.app/icon.png`
- `curl -I https://uspu-schedule.vercel.app/api/telegram/webhook` возвращает 405 (POST only)

## Чего нет

- Не выполнялся деплой в ваш Vercel или push с вашей GitHub-учётной записи: это делает скрипт в WSL.
- Не выполнялось реальное тестирование отправки ботом без токена. HTML-форматтер, маршруты и тесты подготовлены.
- Favicon в этом пакете выполнен как открытая книга с прозрачностью; для использования в точности другого присланного логотипа понадобится его исходный PNG.
